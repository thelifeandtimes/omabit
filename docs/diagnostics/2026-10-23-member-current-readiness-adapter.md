# Current-member readiness adapter after peer replacement

The read-only adapter reconstructs each exact current container contract from
causal history. It checks retained parent/pier identity, complete namespace
membership, publication and full process metadata before and after credential-free
HTTP identity. Replacement process start times match their completed receipts;
original process continuity is checked across the new bracket. No mutation method
is exposed. This first adapter requires every current member running.

56 inert-engine cases exercise original and replacement targets after generations2
and3. Changed target/peer processes, storage, namespace, engine, stale/unobserved or
arbitrary HTTP, changed caller selection, cancellation and stopped peers refuse.
The fixture permits only inspect/list and fixed namespace-stat commands; preserved
pier file identity/bytes and absence of signals are checked. These cases and the
existing initial/resumed readiness and resumed Stop regressions pass under race in
25.715s; vet is clean.

An initial negative-fixture check looked for a file at its old path after deliberately
renaming its .urb directory. That failure is retained. The corrected check verifies
the same inode and bytes at the retained path. Product validation was unchanged.

This advances M123 to a concrete adapter with source evidence only. Durable
journals, current-context admission/scheduling and mutations remain separate.
No format, public capability, installed service or live ship changed. Appliance24
is frozen before this work, so its outcome cannot qualify this new adapter.
