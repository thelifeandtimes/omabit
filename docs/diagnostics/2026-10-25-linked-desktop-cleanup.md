# Cleanup after the replacement desktop exits

A separate successor_cleanup module writes format2 records under
`desktop-successor-recovery-<id>.json`. Original cleanup/inspection/checkpoint and
runtime writers remain unchanged. The original cleanup reader refuses format2.
The linked reader requires descriptor2, a bound committed collection without a
pending switch, an observably exited compositor, original complete guardian closure,
and no live or unobservable admission owners. Its evidence digest includes lineage.

Preparation records the locked application/session/channel cohort before any remote
cleanup. A rejected deletion leaves that plan intact. Retrying after transport
cleanup verifies the preserved cohort; a verified receipt dispatches no effects and
keeps the same file bytes/inode. Missing or changed ancestor/current evidence, a
changed canonical journal, conflicting requests or an invalid lease refuse intact.
This receipt does not authorize another desktop or reconstruct missing state.

19 focused and 410 full tests pass in fresh namespaces. The first focused trial had
one fixture error: a new cleanup request ID was used to locate the ancestor's
checkpoint. Saving the original path before changing IDs corrected it; the failed
trial is retained. Existing 391-test sources remain byte-identical.

The native run uses source-copied Theme/DMs, inert Omabit/appearance adapters, private
software Wayland, private unlocked Secret Service, and synthetic Eyre. It repeats
the artifact4-to5 continuation, then exits the replacement compositor while its
apps are connected. The QML process exits255 as expected for display loss; its
original guardian reaps the owned tree. Two channels remain remotely undeleted,
demonstrating that process closure alone is insufficient. Wrong-guardian cleanup
refuses before effects; rejected DELETE preserves the prepared record. Two controller
kills (after preparation and after actual cleanup) recover with six channels closed,
six sessions unchanged and the unresolved DM byte-identical, without login/replay.
All29 injected controller kills in the combined scenario pass; all three compositor
exits are0 and all four test scopes are inactive. Historical guard claims can still
say admitted after process loss; original guardian closure and observed process
identity, rather than rewriting those claims, establish that they have ended.

Independent verification checks sources, immutable generations, canonical history,
lineage, reservations, metadata identities/hashes, cleanup records and native reports.
Unchanged immutable plugins are referenced from retained M323 evidence rather than
copied again. Exported evidence contains metadata/code, no keyrings, raw sessions,
account/application-state files or piers. No production resources were touched.

This supersedes M323's missing linked-session transport cleanup for the committed,
bound private scenario only. Durable checkpoint/continuation from authority2,
