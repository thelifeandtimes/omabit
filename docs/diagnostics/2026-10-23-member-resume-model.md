# Retained-pier replacement intent — 2026-10-23

The pure resume model requires a completed clean retirement and a new explicit
operation. It retains the original Stop, exit observation and removal receipts;
Create and Start each have a committed dispatch and a separate acknowledgement.
A returned Create ID survives a late error. Interrupted phases cannot reexecute.
Before Create and Start, complete fresh observations must preserve the initialized
pier, original anchor namespace and exact peer lifecycle. The new container ID
must differ from every original resource. Running is container evidence only,
not Urbit readiness or application recovery.

The driver contract requires resume arguments without bootstrap flags or pill,
exact original pier identity, complete mount/inventory checks and renewed checks
at dispatch. Previous generation must come from accepted durable history; overflow
and zero are refused. The concrete adapter/store must bind that generation to its
actual container contract. The model alone cannot establish this authority.

commit boundary, lost replies, cancellation, stale observations, changed peers,
replaced storage, unknown namespaces and old processes. Constructor/driver/commit
alias checks preserve the original nested evidence. Full project model race tests
