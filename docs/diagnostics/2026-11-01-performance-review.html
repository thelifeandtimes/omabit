All ten targets reviewed

  1. Retain bounded SSH transports

    Keep up to three authenticated connections per private client to match overlapping reports, avoiding repeated handshakes.

  2. Poll according to visibility and pending work

    Two seconds while the panel, monitor or action is active; 30 seconds when hidden. Opening requests a fresh observation immediately using the same collector.

  3. Remove repeated Python startup

    The existing bootstrap lease process observes selection changes. It still rereads and validates state and pins.

  4. Stop readiness timers when ready

    The 250 ms activation timer runs during activation or recovery. The lease restart timer runs only when the lease is absent.

  5. Avoid hidden one-second clock updates

    Observations and opening a view update time. Visible views keep their clock and action checks.

  6. Reuse verified metadata within one observation

    A fresh validated Hello is shared by that observation's reports. Per-connection identity and authorization checks remain in place.

  7. Keep existing runner caches

    No extra collector cache added. Existing 30-second native and five-second engine caches already bound the work; another cache offers no hidden-poll reduction and adds invalidation risk.

  8. Skip unchanged sample-map replacements

    History maps keep identity when data is unchanged. Changed samples, gaps, runtime replacement and history limits retain existing behavior.

  9. Batch snapshot history reads

    Preserve ordering, current-runtime binding, the 128-record limit per instance and validation. One-ship reads use the original query. No schema migration.

  10. Check background helper lifetimes

    Fifty panel/monitor cycles retained one collector and stable file descriptors, with clean drain. Keep SSH liveness and revocation checks. No additional UPower observer was justified.

What to review now

  1. Check the update policy. The hidden menubar state may be up to 30 seconds old. Opening the panel or monitor asks for fresh data immediately; visible views and pending actions use two-second polling.
  2. Review the evidence above. The largest improvements are in idle work and connection churn. This page separates measured component gains from battery-life claims.
  3. Review the release boundary. This is a source review candidate. Your installed Omabit remains unchanged. There is no new install command or published release for this pass.

After a paired release candidate is qualified, the practical DEV review should cover opening/closing and minimizing views, idle CPU with no local piers, disconnect/reconnect, live status during a disposable ship action, and unchanged layout.
