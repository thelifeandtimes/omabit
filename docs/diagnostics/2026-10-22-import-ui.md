# Guided import UI and disposable VM boundary

The actual import and recovery components passed an offscreen Qt walkthrough with
copied `Model.js` and verbatim shipped service callbacks. Final UI evidence:
`/tmp/omabit-import-ui-20261022-02`. The
[manifest](2026-10-22-import-ui.json) records source hashes, exact dispatched
arguments, screenshots, environment, VM inputs and limits. All recorded source
hashes matched when this checkpoint was written. Changes remain unreleased and
uncommitted; no installed plugin or service was changed.

## UI behavior exercised

- A refused preview displays the quoted offending entry and permission reason;
  import remains disabled. The wrapper supplies the same plain-text diagnostic
  presentation as Storage; the full Storage/Monitor shell is not instantiated.
- Preview displays the named child under the selected custom root. Changing roots
  clears consent, an expired preview cannot submit, and a new review needs consent.
- Actual service callbacks send the exact runner identity, source, destination,
  fingerprint, detected ship, HTTP port and stopped/identify flags. Double clicks
  submit one request. No automatic Start, deletion or new runtime command occurs.
- A lost acknowledgement remains uncertain, locks the source against resubmission,
  and reports that an unavailable runner may still be importing. A later matching
  receipt restores copying progress and phase history.
- Failed enrollment preserves the request and shows retained-data guidance.
  Recovery binds the current revision. Stale recovery is refused; a rejected
  request needs an explicit new review. Success says the ship remains stopped.
- A separate in-place import says **Enroll stopped pier**. Its successful receipt
  reaches completion while the earlier request remains retained.

Five screenshots were captured; diagnostic, plan, copying, recovery and completion
states are retained in the evidence directory. Diagnostic, plan, recovered and
complete layouts were visually inspected. Both panel model/state regression
scripts also passed. The import note now describes private Ethereum devnets as
unavailable and states that fake/live detection does not verify chain configuration.

Run this isolated fixture with:


It requires Qt's `qml6`. It clears inherited environment and uses private HOME/XDG

runner helper, Docker daemon, host D-Bus/keyring or compositor socket.

## VM boundary preparation

This execution environment has no accessible `/dev/kvm` and did not have QEMU
installed. The existing qualification package downloader prepared signature-checked
QEMU 11.1.2 packages in `/tmp/omabit-import-vm-tools-20261022`, using the configured
Omarchy mirror and installed public package keyrings. Packages were extracted into
that private bundle; nothing was installed into the host package database.

The reusable `scripts/qualification/imports/smoke.py` driver booted a minimal
Linux 7.2.11 guest with software emulation. Final evidence:
`/tmp/omabit-import-vm-smoke-20261022-04`. Guest PID 1 verified its explicit marker,
QEMU DMI and absence of a home mount, emitted readiness, and powered off. Exit 0;
no timeout or log truncation. The driver retains command, exact binary/library/
firmware/kernel/init hashes and bounded console evidence.

The guest has no network device, disks, host filesystem shares or ship data. QEMU
itself runs in private Bubblewrap user/network/PID/mount namespaces, with only
read-only OS runtime, copied artifacts/tool bundle and fresh lab storage mounted.
The unique scope caps memory at 768 MiB, swap at zero, CPU at one core and tasks at
64; the guest has 512 MiB. Timeouts terminate only the spawned process group.
