# Initial member readiness evidence — 2026-10-23

The pure model reconstructs the complete original project generation from serial
member launch receipts. It requires all members, matching anchor and peer bindings,
unique operation identities and the original running-container namespace evidence.
The result is a selection for fresh observation, not authority from cached state.

A read-only collection attempt first checks the complete running project. It then
captures pier and `.urb` identities, queries the selected loopback `/~/host`
endpoint without credentials, and repeats storage and full project observation.
Exact parent/pier identities, expected ship, unchanged publications/namespaces and
a fresh bounded observation window are required before any evidence is returned.
Partial results and provider/HTTP details do not escape on failure. Mutable driver
arguments and observation buffers cannot rewrite retained evidence.

The resulting receipt is explicitly historical. The original empty-storage,
anchor-Start and member-launch receipts stay immutable. Persistence, concrete
collection, automatic scheduling and current UI status remain separate work.
Forty-five inert cases plus focused project race regressions and vet pass, covering
inconsistent launches, stopped peers, stale observations, changed namespace/pier,
wrong ship, cancellation and altered receipt fields. Schema27 is unchanged; no
ship or engine was accessed by these tests. VM23-12 remains separately frozen at
the earlier member-launch fixture and cannot qualify this model.
