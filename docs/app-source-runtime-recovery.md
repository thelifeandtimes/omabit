# App source recovery across a replacement runtime — development contract

Implementation is in progress. The typed review/receipt model has source tests;
there is no persistent mapping, migration, live observer, API, CLI/MCP tool or
runtime rebinding yet. Existing source operations continue to require their exact
original process. No receipt/database edit is an upgrade or recovery procedure.

The first milestone preserves an unfinished plan2 after a supported Stop/Start
of its existing disposable pier. The original plan, actor, request/phase IDs,
payloads, event hashes and held namespace lease remain immutable. A new linked
operator receipt can bind a separately verified replacement process; it cannot
turn an acknowledged unknown write into permission to dispatch it again. Legacy
plan1 and key rotation need separate policies and remain unsupported.

Review must name the original request/plan/header, exact event prefix and current
phase/state, previous recovery head and full prior container. Current evidence
must independently establish the registered replacement container, process PID/
start, host boot, engine, image/runtime, launch/network/namespace context, same
pier continuity, configuration and unchanged verified framework baseline. Current
actor/role, ownership and management/resource fences remain authoritative.

For an unknown dispatched/acknowledged phase, this first route requires native
read-after proof of that exact original effect. For an undispatched phase, it
requires the complete verified retained native prefix. Unowned/drifted roots,
insufficient evidence, a refused/abandoned/complete operation, changed actor,
configuration/pier/project generation/framework or unavailable evidence refuse.
All compiler/conditional reads must complete inside authenticated read capture
with confirmed cleanup, including any recompilation required by recovery.

Apply must authenticate the original operator, require explicit confirmation,
reobserve every reviewed fact and compare the actual fresh review. A digest is a
content binding, not a signature or substitute for observation. Enforce a five
minute lifetime and exact transactional CAS on original event prefix and recovery
head. Add an immutable linked receipt without changing the plan/event prefix.
Later phase observation remains a separate original app journal event. A saved
lookup after lost reply or manager restart must replay the original audit receipt
without native calls, source bytes, new IDs or repeated effects.

A trusted runtime adapter may then fence that approved process while constructing
the unchanged original native requests. Changing `Plan.Binding` would invalidate
the original digest and payload identity and is prohibited. Every subsequent
admission still checks current policy and the exact approved process; revocation
or another PID/container/namespace transition refuses. Historical receipts remain
readable after later legitimate app progress; an old review never acquires fresh
CAS authority. Rebinding sends no Start/Stop/signal and grants no Commit or other
application capability.

Persistent implementation requires a new managed schema boundary and validation
of the linked audit ancestry. Before promotion, build an actual original62 writer/
reader fixture containing dispatched/acknowledged uncertainty and its lease;
preserve all previous tables/events/access across repeated migration/reopen,
rollback and process death. Prove genuine62-reader refusal of the successor store
unchanged. Add actual SQLite/HTTP and CLI/official-SDK parity for stale/concurrent
review, role/actor drift, lost apply reply, replay without cache/runtime and exact
single dispatch after resumed work. Do not publish private original databases.

Native qualification should clone the fixed task-only pending VM read-only into
a fresh overlay, suppress startup resume before systemd, and use supported
lifecycle actions on that disposable app fixture only. It must preserve the
original17-event prefix and peers, recover the acknowledged phase by observation,
finish the original source, update state/code, replace the runtime again and
verify state/replay through matching artifacts. The original VM remains unchanged
until a separately reviewed retention decision. No fresh bootstrap is required.
Use measured scratch within48GiB and one runtime experiment; compressed immutable
inputs expanded in guest tmpfs may reduce disk copies while preserving exact
executable pins. The fresh-peer bootstrap failure remains failed evidence.

Recording3 storage, remaining CLI/MCP coverage, project containment, preserved DEV
and final installed upgrades remain separate tracks. This contract changes no
production or manual-review namespace and advertises no workflow readiness.
