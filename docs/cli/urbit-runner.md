# urbit-runner command reference

Generated from the built command help. Do not edit this file by hand.

Global options precede the command. Command options follow its positional arguments.

## Overview

```text
Usage: urbit-runner COMMAND
       urbit-runner --development-root /srv/dev/urbit COMMAND

The separate development root requires its own root-owned owner.json. Only
serve-development, resource-policy and state-schema are allowed in that mode.
It never uses the installed host's state, Docker socket or SSH grants.

Commands:
  state-schema               Print this binary's persistent state schema version.
  install-host --owner USER --bundle DIR --public-key FILE --acknowledge-host-changes
                              Install the owner's rootless engine, access and services.
  authorize-desktop --public-key FILE --expected-runner-id ID --ssh-connection TUPLE
                    --acknowledge-host-changes [--role operator|observer] [--revoke]
                             Add/revoke a restricted key on the existing SSH endpoint.
  remote-bootstrap           Interactive, OS-authorized remote onboarding helper.
  prepare-ssh --output DIR --public-key FILE --role operator|observer
                             Write inert loopback SSH review configuration.
  ssh-authorized-key --public-key FILE --role operator|observer
                             Print a restricted SSH grant for review.
  ssh-bridge --socket PATH --authorized-keys FILE --fingerprint ID
                             Fixed-command SSH RPC bridge (development fixtures).
  preflight                  Read local prerequisites without contacting Docker.
  doctor                     Alias for metadata-only preflight.
  host-check [--format json|text] [--live]
                             Report native packages; --live probes the installed owner's engine.
  verify-host-packages --acknowledge-local-verification [--fetch-missing] [--format json|text]
                             Local root: authenticate native packages; optional download-only fetch.
  repair-engine-guard --acknowledge-host-changes [--fetch-missing] [--format json|text]
                             Local root: refresh recognized guards/units; optional download-only fetch.
  setup-plan                 Show the rootless installation review plan as JSON.
  prepare-rootless --output /absolute/new/directory
                             Fetch pinned, inert rootless setup review artifacts.
  resource-policy show|set    View/tune new and existing ship resource thresholds.
  runtime-plan               Describe the pinned disposable-runtime checkpoint.
  qualify-runtime --acknowledge-disposable-run
                             Run it as the installed pier owner (never as root).
  http-plan                  Describe the host-loopback HTTP checkpoint.
  qualify-http --acknowledge-disposable-run
                             Test private HTTP publication and replacement.
  meld-plan [--format text]  Describe disposable offline-meld qualification.
  qualify-meld --acknowledge-disposable-run [--format text]
                             Test offline meld and same-pier restart.
  epochs-plan [--format text]
                             Describe disposable offline-roll qualification.
  qualify-epochs --acknowledge-disposable-run [--format text]
                             Test three rolls, restarts, and a prefix preview.
  prune-plan [--format text]
                             Describe destructive disposable-prefix qualification.
  qualify-prune --acknowledge-disposable-run [--format text]
                             Test exact prefix deletion and latest-epoch recovery.
  prefix-plan [--format text]
                             Describe snapshot-bearing and repeated-prefix tests.
  qualify-prefix --acknowledge-disposable-run [--format text]
                             Test two successive deletions/recoveries on a new fake.
  import-plan [--format text]
                             Describe bounded stopped-pier copy qualification.
  qualify-import --acknowledge-disposable-run [--format text]
                             Copy a new stopped fake pier and resume the copy twice.
  comet-plan [--format text]
                             Describe fresh disposable-comet qualification.
  qualify-comet --acknowledge-disposable-run [--format text]
                             Create a new comet and verify initialized-pier resume.
  comet-maintenance-plan [--format text]
                             Describe fresh-comet pack/meld qualification.
  qualify-comet-maintenance --acknowledge-disposable-run [--format text]
                             Test offline pack/meld and identity-preserving restarts.
  comet-epochs-plan [--format text]
                             Describe fresh-comet epoch-roll qualification.
  qualify-comet-epochs --acknowledge-disposable-run [--format text]
                             Test three rolls, exact-identity restarts and preview.
  comet-prefix-plan [--format text]
                             Describe destructive disposable-comet prefix tests.
  qualify-comet-prefix --acknowledge-disposable-run [--format text]
                             Test repeated prefix deletion and latest-epoch recovery.
  serve-fake --acknowledge-development
                             Serve the persistent fake-ship management API.
  serve-development --acknowledge-development [--resume-running]
                             Serve development management; optional resolved startup resume.
  demo --socket /private/directory/runner.sock [--operation-delay 2s]
                             Run the checkpoint 1 in-memory simulator.

install-host performs explicitly authorized host setup for an existing Unix user.
Qualification commands create new disposable ships and runtime resources.
The development management API supports operator-authorized owned-key bootstrap;
qualification commands do not accept existing production identities or piers.
No command installs system packages. qualify-comet creates a new disposable comet.
Use COMMAND --help for details.
```

## demo

```text
Usage: urbit-runner demo --socket /private/directory/runner.sock [--operation-delay 2s]

Runs a local, memory-only simulator with two synthetic instances. No Docker,
Vere, network ports, credentials, or real piers are used. All history is lost
when the simulator exits. The socket directory must already exist, be owned by
the current user, and have no group/other permissions (normally mode 0700).
```

## install-host

```text
Usage: urbit-runner install-host --owner USER --bundle DIR --public-key FILE --acknowledge-host-changes

Runs the runner and separate rootless Docker engine as the selected existing Unix
user. Creates /srv/urbit/piers for that owner and installs restricted management SSH
and boot services. Preserves the login shell, personal SSH and unrelated Docker.
Legacy dedicated-account installations require explicit retirement/migration.

Add --offline-upgrade for the one-time schema19 compatibility bridge. Finish work
and stop only the owner's urbit-runner.service first. The installer requires the
original runtime flock, no foreground listener and no unresolved jobs, then
transactionally upgrades/fences state before activating the retained new binary.
Rerun the same command after interruption; never reset/re-enroll or lower schema.
See docs/management-offline-upgrade.md. Normal updates use online quiescence.
```

## qualify-comet

```text
Usage: urbit-runner qualify-comet --acknowledge-disposable-run [--format json|text]

Creates a NEW DISPOSABLE COMET using the pinned Vere binary and pill. No existing
pier, supplied identity or key is accepted. Management must be stopped. The comet
can contact the network through its owned NAT bridge. Only host-loopback HTTP is
published; host Ames/UDP, clearweb and remote exposure remain unqualified.
Requires >=5 GiB available RAM and >=8 GiB disk, checked before creation and resume.
Limits: 4 GiB RAM, no extra swap, two CPUs, 256 PIDs, loom 31. Initial readiness and
resume each have a 20-minute bound. Public comet identity must survive replacement.
No automatic creation retry. Partial provisioning remains quarantined after cleanup.
Three containers and the bridge are removed; the private identity-bearing pier
and report are retained. This is development qualification, not production support.
```

## qualify-comet-epochs

```text
Usage: urbit-runner qualify-comet-epochs --acknowledge-disposable-run [--format json|text]

Creates a NEW DISPOSABLE COMET with outbound NAT and loopback-only HTTP.
Management must be stopped. Three network-isolated rolls must each create exactly
one newer snapshot-bearing epoch, with an unchanged-identity restart after each.
A final replacement rechecks all four epochs; an oldest-only preview retains three.
No epoch is deleted. No managed comet roll/retention capability is enabled here.
Fresh admission: 5 GiB available RAM / 8 GiB disk before expensive work.
Limits: 4 GiB RAM, no extra swap, two CPUs, 256 PIDs, loom 31. Readiness is bounded
at 20 minutes and each utility at 10 minutes. No existing path/key/image overrides.
Uncertain rolls or changed identity remain quarantined; no automatic retry.
Nine containers and the bridge are removed; the private pier/report are retained.
```

```text
Usage: urbit-runner qualify-comet-maintenance --acknowledge-disposable-run [--format json|text]

```

## qualify-comet-prefix

```text
Usage: urbit-runner qualify-comet-prefix --acknowledge-disposable-run [--format json|text]

DESTRUCTIVE qualification confined to a NEW DISPOSABLE COMET, never an existing pier.
Management must be stopped. Runtime uses outbound NAT and loopback-only HTTP.
Four isolated rolls/restarts create five epochs. Delete the oldest two, retain three,
verify ordinary restart, then remove this disposable current checkpoint and run
network-isolated play --full to recover from the latest retained epoch. Verify an
identity-preserving restart, delete the oldest remaining epoch (retain newest two),
then repeat ordinary restart, checkpoint-loss/recovery and recovered restart.
A final replacement must preserve the same public identity and two retained epochs.
No existing path, key, identity, cutoff or image override. No managed pruning enabled.
Fresh admission requires 5 GiB available RAM / 8 GiB free disk before expensive work.
Limits: 4 GiB RAM, no extra swap, two CPUs, 256 PIDs, loom 31; 20-minute readiness and
10-minute utility bounds. Partial deletion/recovery stays quarantined without retry.
Seventeen containers and the bridge are removed; the private pier/report remain.
```

## qualify-epochs

```text
Usage: urbit-runner qualify-epochs --acknowledge-disposable-run [--format json|text]

DEVELOPMENT multi-epoch qualification. Run as the dedicated account with management
stopped. Creates a fresh isolated fake, verifies its initial epoch, then performs
three explicit offline rolls, each followed by a same-pier restart and clean stop.
Requires 5 GiB available RAM and 8 GiB disk, rechecked before every roll.
Container limits: 4 GiB RAM, no additional swap, two CPUs, 256 PIDs, loom 31.
Each utility/readiness phase has a ten-minute deadline. Downloads the pinned image
and ~207 MiB pill. Snapshots/epochs and the private report are retained afterward.
An uncertain roll is quarantined; cleanup does not clear it or trigger a retry.
The final preview selects the oldest epoch and retains three; no epoch is deleted.
This does not qualify retained-suffix replay or backup recovery. Use --format text
for readable progress and results. Ctrl+C requests bounded resource cleanup.
```

## qualify-http

```text
Usage: urbit-runner qualify-http --acknowledge-disposable-run [--format json|text]

DEVELOPMENT host HTTP checkpoint. Run as the dedicated urbit-runner account,
never root. Creates a fresh fake zod, a per-run NAT bridge, and only an
ephemeral IPv4 loopback publication. Verifies public Eyre identity from the host,
replaces the container and reconnects, then cleans up owned containers/network.
The dedicated bridge permits normal outbound access; Ames remains disabled.
No real identity, existing pier, login cookie, Ames port or control socket is used.
Requires >=5 GiB available RAM and >=8 GiB free disk. Downloads ~207 MiB of pill
data plus the pinned image. Progress is JSON lines on stderr; the report is on
stdout and in private storage. Cancellation cleanup can take several minutes.
Use --format text for readable progress and results.
```

## qualify-import

```text
Usage: urbit-runner qualify-import --acknowledge-disposable-run [--format json|text]

DEVELOPMENT stopped-pier transfer qualification on a newly created isolated fake.
Management must be stopped. Boots and cleanly stops a fresh fake, reserves the
original source, copies it into fresh owner-only storage, then resumes the copied
pier twice without creation flags. Source content must remain unchanged.
Tree limits: 8192 entries, depth 32, 100 GB logical bytes; reject symlinks, hardlinked
files, special files, cross-device entries, ownership changes and concurrent writes.
Copy admission requires source logical bytes plus 8 GiB free disk; boot/resume
requires at least 5 GiB available RAM. No existing-pier, path, key or image input.
Four containers are removed; both piers and the report remain for review.
Interrupted copies/resumes remain quarantined; cleanup does not clear uncertainty.
```

## qualify-prefix

```text
Usage: urbit-runner qualify-prefix --acknowledge-disposable-run [--format json|text]

DESTRUCTIVE DEVELOPMENT qualification on a newly created isolated fake only.
```

## qualify-prune

```text
Usage: urbit-runner qualify-prune --acknowledge-disposable-run [--format json|text]

DESTRUCTIVE DEVELOPMENT qualification, confined to a newly created isolated fake.
Run as the dedicated account with management stopped. Creates four epochs using
three rolls/restarts, then revalidates and deletes ONLY the oldest epoch 0i0.
Three newer epochs must retain their exact metadata fingerprints. After ordinary
restart, removes the disposable current checkpoint and runs pinned play --full,
which restores from the LATEST retained epoch, followed by another HTTP restart.
Requires 5 GiB available RAM / 8 GiB free disk; fixed 4 GiB/no-extra-swap containers.
No existing-pier, cutoff, path or image override. Partial deletion/recovery stays
quarantined without automatic retries. Owned containers are cleaned up; data and
report are retained. This does not qualify older-epoch recovery or managed prune.
Use --format text for readable progress/results. Let cancellation cleanup finish.
```

## repair-engine-guard

```text
Usage: urbit-runner repair-engine-guard --acknowledge-host-changes [--fetch-missing] [--format json|text]

Run locally as root after reviewing host-check and package authentication evidence.
Default: offline verification of cached native packages. --fetch-missing explicitly
permits standard native-package download-only commands for missing verification
artifacts. The exact installed builds must still be available from configured native
repositories; unavailable builds remain unresolved. It does not install or update packages or import keys.
Updates only recognized generated engine guards/units and reloads an already active
user manager. Preserves administrator edits; never starts or restarts the engine.
The result includes updated, reloaded and partial, including on failure.
Time limit: 2 minutes offline; 10 minutes with --fetch-missing. An earlier caller
deadline still applies. This command is local-only, with no remote root RPC.
```

## resource-policy

```text
Usage: urbit-runner resource-policy show
       urbit-runner resource-policy set --phase new|existing [--minimum-ram-mib N]
         [--minimum-disk-mib N] [--recommended-ram-mib N] [--recommended-disk-mib N]
```

## serve-development

```text
Usage: urbit-runner serve-development --acknowledge-development [--resume-running]

Serve the installed pier-owner development runner with fake/comet creation, owned-key
bootstrap, stopped-pier enrollment, maintenance and host handoff. Comets generate
their identity internally. HTTP is loopback-only; owned ships publish configured Ames UDP.
Collector enrollment must explicitly accept mode development-managed while
retaining the same runner ID. Private state has explicit schema/downgrade guards.
Validated settings support loom 30..34 (default 31) and CLI-only native control
for every ship class (default off). Inspect snapshot runtime status for recorded
launch settings and the host-local socket path.
Start/stop are explicit; incomplete bootstrap is quarantined, never retried.
With --resume-running, startup may replace terminal runtime containers for
initialized ships whose persisted desired state is running. Each ship gets at most
one journaled attempt per host boot. Nonzero exits require a recorded healthy prior
boot; intentionally stopped, interrupted and independently uncertain ships are skipped.

Warning: known ship-crash bug
Primarily for development. Leave disabled for routine use: it is unnecessary and adds risk.

This pinned Vere build has a known crash bug when a client disconnects with replies pending. Keep clients connected until every reply has been received. Do not kill clients or use short timeouts.

conn.sock grants full ship-control authority, not health-only access.
```

```text
Usage: urbit-runner serve-fake --acknowledge-development
```

## verify-host-packages

```text
Usage: urbit-runner verify-host-packages --acknowledge-local-verification [--fetch-missing] [--format json|text]

Run locally as root after reviewing the host metadata. Default: offline verification
```
