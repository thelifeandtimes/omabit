# Ordinary recording pressure qualification

This fresh offline capsule extends the scoped recording pilot evidence. Read
`docs/experiment-isolation.md` before use. It never opens installed host sockets,
existing ships, manual DEV, tmux or production data. No work occurs without
`--run`; an ended or failed output directory cannot resume.

Pass clean matching CLI/collector/runner and source-pinned `managed.test`, the
previously frozen release-upgrade PID1, pinned pristine portable base, rootless
bundle and exact runtime/pill inputs. Use a fresh
`/tmp/omabit-issues-recording-pressure-vm-NN`. The host holds the shared runtime
lock and admits2304MiB scratch (including a1664MiB hard root-file ceiling) under the complete aggregate storage budget. One
bounded supervisor and one offline10GiB/no-swap/one-CPU VM scope are permitted;
no source builds run during the VM.

The installed candidate opts into ordinary recording and creates one new fake.
Its recorder uses a640MiB guest-only tmpfs while jobs, state and the pier remain
on the disposable root disk. Three same-pier sessions check:

- A fixed1.5MiB binary line and64 stderr messages sent to the fresh container's
  output pipes. These are explicitly synthetic transport bytes, not a claimed
  application workload or arbitrary user commands. The real detached worker and
  Docker output transport capture them. An independent bounded decoder verifies
  segment links, frame digests, sequence/timing and exact original bytes.
- A1MiB encoded session limit, explicit incomplete coverage, continued native
  process identity and normal Stop/drain without rewriting the original prefix.
- Actual free space below the512MiB configured reserve. A bounded filler on that
  separate tmpfs leaves jobs/state/pier storage available. Missing gap-frame
  persistence must remain explicit in the saved result. Removing only the filler
  cannot resume capture or rewrite its saved original prefix.

The retained three jobs must refuse another recording admission without eviction
or another runtime/job. An explicit final Stop restores stopped intent after the
failed Start. Closed original recordings remain immutable across later sessions.
Bounded copies preserve tmpfs evidence on the ended VM disk, including failures.
The host prints only compact gates and the full private proof's hash.

This is not a host reboot, all-filesystems-full, existing-process adoption,
project/maintenance factory, automatic deletion or age-enforcement test. It does
not qualify release/DEV upgrades by itself. The whole native run and independent
post-run checks are pending until recorded; inert guard passes are not native
qualification.
