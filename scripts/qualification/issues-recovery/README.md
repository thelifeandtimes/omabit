# Offline development upgrade and interrupted Stop gate

`run.py` does no work without `--run` and explicit inputs. It accepts only a fresh
`/tmp/omabit-issues-vm-NN` capsule and clean committed source. Published0.4.0 tools,
the matching Recommended Apps pill, the pinned standard project pill/OCI image,
the entire declared pristine portable input tree and matching candidate binaries
are rehashed before launch. The original read-only not-onboarded base receives a
new COW overlay; existing overlays, manual-review state and host services are
never exposed. The payload is read-only and contains no user's state or keys.

The VM has no NIC, one CPU,8GiB RAM within a10GiB/no-swap/512-task scope, a40-minute
deadline and4GiB additional scratch admission. Aggregate DEV/evidence, temporary
outputs and shared compiler/module/build caches count toward the default40GiB
cap;48GiB is accepted only for the user's explicitly authorized temporary goal.
One runtime experiment may be active. The private lock covers this launcher;
the operator must also ensure no other kind of runtime experiment is active.
Storage/log/deadline failures stop only the uniquely created VM scope and retain
its failure evidence. A pruned or existing capsule is never resumed.

The private guest installs actual published0.4.0 and boots two new recommended
fake ships, leaving one intentionally stopped. The actual installer upgrades to
the source snapshot. It checks identities, registrations, history, running/stopped
intent, access, engine invocation and container processes, schema59→60, unchanged
refusal by the old writer, and restart of the new installed manager. This is a
development artifact qualification, not a new stable version or publication.

It then stops the running upgrade witness and creates a separate new core-pill
project through the public restricted-SSH collector. Adding a new peer must keep
the original peer's process intact. A separately hashed Go test manager embeds
the real backend and the same host lock/API/store. Its only injected behavior is
to block before saving the final `stopped` phase **after** real native code has
observed a clean exit; the parent kills that exact helper PID/start/executable.
No database row is edited. Restarting the installed runner records interruption.
Ordinary Start must remain fenced until saved diagnosis, exact live review and
audited reconciliation. The original receipt stays immutable. Reconciliation and
guarded lookup must not signal or Start. A second test manager refuses recovery
observation, proving exact receipt replay after store reopen needs no observer.
Docker events for only the owned selected container must show one SIGTERM.
Supported Start then resumes the same pier without disturbing its peer. All new
ships must stop cleanly before the guest powers off.

Reports and raw bounded command evidence stay on the private fresh overlay and
in the capsule's console/result files. Publish only a separately reviewed compact
report. The helper is a fault-injected test binary, never the installed runner;
record both hashes. Passing this gate does not prove the historical timing race,
other interrupted phases, a desktop UI or DEV deployment, multi-host upgrades,
Grubbery, or production permission. Later source changes need matching artifacts
and renewed relevant qualification.
